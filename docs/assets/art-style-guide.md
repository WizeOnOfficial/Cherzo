# Art Style Guide — 3D Assets

**Status:** Accepted direction (2026-10-17). Applies to every 3D asset made for this project.
**Owner:** Asset pipeline (Blender). Integration (prefabs, scripts, scene wiring) is done separately in Unity.

## 1. Look in one sentence

A clean white-and-orange industrial chemical facility, built **low-poly and flat-shaded**, seen through the project's **retro pixel filter** (URP render scale 0.2 + dither). The mood (emergency, evacuation) comes from **lighting** in Unity — red alarm lights, exit signs, flicker — not from the assets themselves. One asset set therefore works for both "normal" and "disaster" states.

## 2. Rules that follow from the pixel filter

At render scale 0.2 a 1920×1080 screen is rendered at ~384×216.

- Read by **silhouette and colour blocks**, not detail. Small bolts, thin labels and text vanish.
- Minimum feature size seen in normal play: about **5 cm**. Anything smaller only matters for close-up (Cinemachine focus) objects.
- Strong value contrast between neighbouring parts (light panel next to dark gap).
- No smooth shading, no normal maps, no realistic textures.
- Interactable objects get a little more detail and a **readable accent colour** (orange, yellow, cyan screen) so players can spot them.

## 3. Palette (single texture)

- File: `Assets/Art/Textures/T_Palette.png` (128×128, 8×8 swatches of 16 px — large enough that Unity's default bilinear filter and mipmaps don't bleed colours). Overview: [`palette_sheet.png`](palette_sheet.png).
- Every model takes its colours from this texture. Faces' UVs are collapsed onto one swatch centre.
- Swatch names: `<family>_<shade>`, shade 0 = lightest … 3 = darkest.

| Family | Use |
|---|---|
| `white` | Facility panels, walls, lab furniture (dominant) |
| `metal` | Steel, machinery, frames, pipes |
| `char` | Rubber, black plastic, gaps, shadows |
| `orange` | **Brand / hazard accent** — stripes, caps, signage |
| `yellow` | Safety yellow, warning labels, floor stripes |
| `red` | Emergency, alarm, "denied" |
| `green` | LEDs, "granted", terminals |
| `cyan` | Screens, UI glow |
| `uniform` | MC work shirt (blue-grey) |
| `navy` | Trousers, dark accents |
| `wood` | Office desks, crates |
| `skin` | Hands / characters |
| `toxic` | **The leaked liquid** — acid yellow-green, always emissive |
| `brass` | Fuse caps, terminals, contacts |
| `concrete` | Floors, raw walls |
| `glass` | Windows, lab glass tint |

Changing a colour in the palette PNG recolours the whole game. Keep swatch positions stable — moving a swatch breaks every model that uses it.

The palette is generated by `ArtSource/_tools/chemkit.py` (`FAMILIES` list). Edit there, then regenerate.

## 4. Materials

Only two materials are used by the models:

| Material | Unity shader | Settings |
|---|---|---|
| `M_Palette` | URP/Lit | Base Map = `T_Palette`, Metallic 0, Smoothness ~0.1 |
| `M_Palette_Emit` | URP/Lit | Same as above + Emission ON, Emission Map = `T_Palette`, Emission colour white (HDR intensity ~1.5–2) |

Emissive parts: screens, LEDs, indicator lamps, exit signs, toxic liquid.

**Texture import settings for `T_Palette.png`:** Texture Type Default, sRGB ON, **Filter Mode = Point (no filter)**, **Generate Mip Maps = OFF**, Compression = None, Wrap Mode = Clamp.

## 5. Scale, orientation, pivots

- 1 Blender unit = 1 metre. Unity import scale factor 1.
- Asset **front faces Blender −Y** → becomes **Unity +Z (`transform.forward`)** after export.
- Pivot rules:
  - Floor props: bottom centre.
  - Wall-mounted props: back-centre-bottom (the point that touches the wall).
  - Moving parts (doors, covers, levers): at the hinge/rotation axis, with zero rotation in rest pose.
  - Pickups: geometric centre.
- Reference heights: door 2.1 m, ceiling 3.0 m, desk 0.75 m, wall panels mounted ~1.0–1.2 m (eye level 1.6 m).

## 6. Budgets (triangles, visual meshes only)

| Category | Budget |
|---|---|
| Small pickup (card, fuse, note) | ≤ 300 |
| Interactable device (panel, reader, computer) | ≤ 2,000 |
| Furniture / prop | ≤ 800 |
| Large machine | ≤ 4,000 |
| First-person hands | ≤ 2,500 |
| Whole room (structure + props) | ≤ 40,000 |

## 7. Naming

| Thing | Pattern | Example |
|---|---|---|
| FBX file | `SM_<Asset>.fbx` | `SM_ControlPanel.fbx` |
| Blender source | `ArtSource/<Category>/<Asset>.blend` | `ArtSource/Interactables/ControlPanel.blend` |
| Root object | `<Asset>` | `ControlPanel` |
| Parts | `<Asset>_<Part>` or meaningful child names | `Cover`, `CardReader_Screen` |
| Collider mesh | `<Part>_COL` | `ControlPanel_COL` |
| Attachment point | `Socket_<What>` (empty) | `Socket_ExternalFuse` |
| Camera close-up target | `CamFocus_<What>` (empty) | `CamFocus_ControlPanel` |
| Room file | `Room_<Name>` | `Room_MainLobby` |

Names are stable: scripts and prefabs may rely on child names. Renaming a child is a breaking change and must be noted in the handoff.

## 8. Hierarchy

Every asset is delivered as **one root with named children**. Parts that move, change state, or are interacted with separately are always separate children. Example:

```text
ControlPanel
├─ Housing
├─ Cover            (pivot on hinge; rotate local Y to open)
├─ FuseBay ...      (fuses as separate children)
├─ CardReader       (screen + LED as separate children)
├─ HiddenNote
├─ Socket_* / CamFocus_*   (empties)
└─ *_COL            (collider meshes)
```

Rooms (later) follow: `Room_X / Structure / Props / Interactables / Doors / Colliders`.

## 9. Colliders

- Every asset ships with simplified **collider meshes** as children named `*_COL` (a few boxes; far fewer triangles than the visual mesh).
- Pickups (Rigidbody objects) use colliders that are **convex**.
- Moving parts get their own collider under that part, so it moves with it and can be raycast separately.
- In Unity: add **Mesh Collider** using that child's mesh, tick **Convex** for pickups, and disable/remove its **Mesh Renderer**.

## 10. Export (done by `chemkit.export_unity_fbx`)

FBX, selected hierarchy only, object types Mesh + Empty, Apply Scale = FBX All, Forward −Z, Up Y, **Apply Transform OFF** (it bakes stray 90° rotations into grandchildren), smoothing = Face, no leaf bones, no animation, textures not embedded. Result: only the root carries the axis conversion; every child has zero rotation and scale 1.

**Unity model import settings:** Bake Axis Conversion **OFF** (Unity's option drops the root's −90° X without rotating the meshes → model lies flat). Instead `ArtAssetPostprocessor` bakes the root rotation into the meshes so the model stands upright with every transform at 0/0/0, Scale Factor 1, Convert Units ON, Read/Write OFF (ON only if a script needs mesh data), Generate Colliders OFF (we ship our own), Normals = Import, Animation Type = None (static assets), Materials → remap `M_Palette` / `M_Palette_Emit` to the project materials.

## 12. Delivery checklist (per asset)

- [ ] Within triangle budget.
- [ ] Only palette materials; emissive parts on `M_Palette_Emit`.
- [ ] Front faces −Y; pivots per §5; moving parts have hinge pivots and zero rest rotation.
- [ ] Children named per §7; colliders `*_COL` present.
- [ ] Preview render (normal + pixel-filter simulation) saved in `ArtSource/_previews/`.
- [ ] FBX exported to `Assets/Art/Models/...`, `.blend` saved in `ArtSource/...`.
- [ ] `asset-registry.md` updated; handoff note lists children, sockets, colliders and the Unity steps.

## 13. Lessons learned (keep applying)

- **Thin things:** real-world thicknesses under ~2 mm (cards, paper, labels) are exaggerated to 2–3 mm so they survive the pixel filter; decals sit 0.3–0.5 mm proud of the surface to avoid z-fighting.
- **Pickup colliders:** convex, and at least **1 cm** thick even if the visual is thinner (thin colliders tunnel through floors).
- **State parts:** anything that changes during play (LEDs, role stripe, screen) is its own child so Unity can toggle/recolour it without touching the rest.
- **Parts that fit together** (fuse ↔ socket) share exact dimensions from the same build script values, and a fit test (import both FBX files, snap to the socket) is done before delivery.
- **Magenta in a Blender re-import** is expected: textures are not embedded (`path_mode = STRIP`); Unity remaps materials.
- **Export:** never use Blender's "Apply Transform" (bake space transform) — it puts 90° rotations on grandchildren. Unity-side, `ArtAssetPostprocessor` bakes the root's axis rotation into the meshes (Unity's own Bake Axis Conversion lays models flat — don't use it).

- **Palette integrity (incident 2026-10-17):** resizing the palette image in place in Blender 5 silently wrote an all-black PNG, and every FBX embedded the black copy. `chemkit.build_palette_image` now writes a fresh image and `assert_palette_ok()` blocks export unless the palette has ≥32 colours. Delivery check: decode the PNG embedded in each FBX and confirm 64 colours (not just that a PNG exists).

## 14. Unity import automation

`Assets/Art/Editor/ArtAssetPostprocessor.cs` enforces §4, §9 and §10 automatically for everything under `Assets/Art/`:
palette texture settings, model import settings, upright orientation (root axis rotation baked into meshes, all transforms 0/0/0), the two palette materials (created if missing
and assigned by material name), and `*_COL` → `MeshCollider` (convex for files under `Models/Pickups/`, renderer removed).
New assets therefore arrive ready: drag the FBX into a scene and it is coloured, oriented and has colliders.
Menu: **Tools > Art Pipeline > Reimport Art Assets** (also runs once automatically per machine).
Keep material names `M_Palette` / `M_Palette_Emit` and the `*_COL` suffix exactly — the automation keys on them.

## 15. Export update (2026-10-17) — assets work with no Unity setup

`chemkit.export_unity_fbx` now (a) pre-bakes the Z-up→Y-up rotation into the meshes so the FBX root and every
child have rotation 0 in Unity with default import settings (model stands upright, front = +Z), and (b) **embeds
the palette texture** in each FBX so Unity's default material import already shows the colours.
Consequence: drag-and-drop works without any script or import setting. Re-exporting all assets is needed after
editing the palette (rerun the build scripts). `ArtAssetPostprocessor` is optional on top (shared materials,
crisp Point filter, automatic `*_COL` colliders).

## 16. CURRENT PIPELINE (2026-10-17, supersedes §4 Unity part, §9 Unity part, §10 import settings, §13 export note, §14)

**No Unity script, no import settings.** Drag the FBX into a scene: it is upright (all transforms 0/0/0, front = +Z)
and coloured (palette embedded; Unity's default material import uses it).

- `ArtAssetPostprocessor.cs` and the generated `M_Palette*.mat` were removed from `Assets/` (parked in `ArtSource/_to_delete/`, safe to delete).
- `*_COL` meshes stay in the `.blend` as size references but are **not exported**.
- **Colliders are added in Unity** with Add Component → **Box Collider** (auto-fits the mesh) on the parts listed in each handoff. Pickups: Box Collider + Rigidbody on the root.
- Palette edits require re-running the build scripts (each FBX carries its own copy of the palette).
- Optional for crisper pixels: select the embedded texture and set Filter Mode = Point (not required).

## 17. Cleanup rule (2026-10-17)

After an asset is delivered, its temporary build script (`build_<Asset>.py`), `__pycache__` and `.blend1` backups are deleted.
What stays: the FBX + palette in `Assets/Art/`, the `.blend` source in `ArtSource/`, previews, and the shared Blender helper
`ArtSource/_tools/chemkit.py` (outside `Assets/`, never used by Unity — needed to produce the next assets consistently).
Later edits are made on the `.blend` (or with a new temporary script that is deleted again after delivery).
Unity needs **no** scripts from this pipeline.
